# 软件工程实践个人项目 —— 论文查重（Python 实现）

## 一、项目简介

本项目实现一个**论文查重算法**：输入一篇原文和一篇在该原文基础上经过增、删、改的 "抄袭版" 论文，输出两者的重复率（0.00 \~ 1.00，精确到小数点后两位）。



* 开发语言：**Python 3**（仅使用标准库，无第三方依赖，`requirements.txt` 中已说明）

* 入口文件：`main.py`，使用方式为 `python main.py [原文文件] [抄袭版文件] [答案文件]`

* 核心算法：**文本预处理 + 2-gram 切分 + 余弦相似度**

* 测试框架：pytest（18 个单元测试用例，全部通过，语句覆盖率 98%）

* 代码质量：经 flake8（Code Quality Analysis 工具）静态检查，**零警告**

测试语料使用《活着》前言与第一章：`orig.txt`（原文，约 29 KB）、`orig_0.8_add.txt`（插入大量杂字的抄袭版，约 34 KB），程序输出答案 `0.90`。

## 三、计算模块接口的设计与实现过程

### 3.1 总体设计

整个程序划分为两层：



* **核心计算层**：负责从 "文本" 到 "相似度" 的全部计算，与文件系统、命令行解耦，便于单元测试直接调用；

* **入口控制层**：`main()` 只负责命令行参数解析、分阶段调用核心层、处理用户可感知的异常、写结果文件。

> n-gram 是一种文本特征提取方法：把文本按连续 n 个字符切分成片段（如 "今天天气晴" 的 2-gram 为 "今天、天天、天气、气晴"），每个片段作为一个特征。中文文本用 2-gram 能同时捕捉相邻字符的组合信息，比单字统计（1-gram）更能反映词序，又比 3-gram 对局部增删改动更鲁棒。
> 余弦相似度（Cosine Similarity）把两份文本各自映射为一个 "特征词频向量"，然后计算两个向量夹角的余弦值，取值 0~1：1 表示完全相同，0 表示毫无公共特征。

模块不定义类，而是由 **7 个职责单一的函数** 组成管道，函数之间通过返回值显式传递数据，无共享可变状态：



```
read\_file ──> preprocess ──> get\_ngrams ──> cosine\_similarity

&#x20;  │                                             │

&#x20;  └──────  compute\_similarity（对外接口）────────┘

&#x20;                       │

&#x20;                write\_answer ──> main（命令行入口，分两阶段异常处理）
```

### 3.2 函数设计



| 函数                               | 输入         | 输出          | 职责                                       |
| -------------------------------- | ---------- | ----------- | ---------------------------------------- |
| `read_file(path)`                | 文件路径       | `str`       | 以 utf-8 读取文件，`errors="ignore"` 忽略无法解码的字节 |
| `preprocess(text)`               | 原始文本       | `str`       | 用预编译正则删除所有标点、空白、换行，只保留中文 / 字母 / 数字       |
| `get_ngrams(text, n=2)`          | 文本、窗口大小    | `list[str]` | 切成连续 n-gram；空串返回 `[]`，长度不足 n 返回 `[text]` |
| `cosine_similarity(t1, t2, n=2)` | 两段已预处理文本   | `float`     | 构建 2-gram 词频向量并计算余弦相似度，空向量返回 0.0         |
| `compute_similarity(orig, copy)` | 两个文件路径     | `float`     | 对外暴露的总接口：读文件→预处理→算相似度                    |
| `write_answer(path, ratio)`      | 输出路径、比率    | 无           | 以 `f"{ratio:.2f}"` 写入答案文件                |
| `main()`                         | `sys.argv` | `int`       | 参数校验、分两阶段异常捕获、调用核心层、返回退出码                |

### 3.3 关键算法说明



1. **预处理**：删除所有非中英数字符。这样 "今天，天气晴！" 与 "今天天气晴" 在特征上完全一致，标点、空格、换行的增删不影响重复率，正对应 "增删改" 抄袭场景中常见的标点改动。正则在模块级预编译（`_PUNCT_PATTERN = re.compile(...)`），避免每次调用重复编译。

2. **2-gram 切分**：以 `text[i:i+2]` 滑动窗口生成连续二元组。原文 "今天是星期天" 切为 "今天、天是、是星、星期、期天"。即使抄袭版把 "星期天" 改成 "周天"、"天气晴" 改成 "天气晴朗"，大部分相邻二元组仍与原文重合，相似度依然很高。

3. **词频向量与余弦**：用 `Counter` 统计各 2-gram 出现次数作为向量分量；点积只遍历两个 Counter 的**交集键**（`set(grams1) & set(grams2)`），避免构造稀疏全向量，空间开销为 O (不同 2-gram 数)；模长用 `sqrt(sum(v*v))` 计算，最终 `dot / (mag1 * mag2)` 即为重复率。

4. **性能优化 —— 遍历较短向量**：点积计算前始终交换使 `grams1` 为键数较少的 Counter，减少循环体执行次数。

5. **边界保护**：任一文本为空（无任何 n-gram 特征）时直接返回 0.0，杜绝除零。（注：原代码中额外的 `if mag1 == 0 or mag2 == 0` 检查经分析为不可达冗余分支 ——Counter 非空时模长必然大于 0—— 已在代码复审中删除，简化了逻辑并提升了覆盖率。）

整体时间复杂度为 O (L₁ + L₂)（L 为文本长度），与文本大小线性相关，实测对 30 KB 级文本计算耗时在毫秒级。

### 3.5 独到之处



1. **核心逻辑与 IO 完全解耦**：`compute_similarity` 只收文件路径返回浮点数，单元测试可以不经过命令行、直接用临时文件驱动核心流程，为自动化测试提供便利。

2. **预处理把 "改动" 翻译成 "特征差异"**：只保留语义载体（中文 / 字母 / 数字），使标点、空格这类无意义差异归零，把重复率计算聚焦在真正的文字增删改上。

3. **交集点积 + 遍历短向量，避免构造高维稀疏向量**：两个 Counter 求交集键后累乘，且始终遍历键数较少的一方，内存与时间只与 "出现过的 2-gram 种类数" 相关，不随文本长度平方增长。

4. **分两阶段异常处理**：`main()` 将 "计算相似度" 和 "写入答案" 放在两个独立的 try 块中，输入文件的 `FileNotFoundError` 与输出文件的 `PermissionError`/`OSError` 分别捕获、分别提示，错误定位更精确。

5. **显式处理空文本、短文本、坏编码**：空串返回 0.0、长度不足 n 返回整体、`errors="ignore"` 容忍非法 UTF-8 字节，行为确定、无除零风险，覆盖了评测中可能出现的边界输入。

## 四、计算模块接口部分的性能改进

> Python 项目对应的性能分析工具是标准库 
>
> **cProfile**
>
> （类似于 C++ 的 VS Profiling Tools / Java 的 JProfiler），可以统计每个函数的调用次数与耗时。改进性能所花费的时间约为 
>
> **45 分钟**
>
> 。

### 4.1 改进思路

先用 cProfile 对真实语料（`orig.txt` 29 KB + `orig_0.8_add.txt` 34 KB）做基准剖析，找出耗时最大的函数，再针对热点逐项优化：



1. **预编译正则**：`preprocess` 中每次调用 `re.sub` 都会经过一次正则编译（虽然 `re` 模块有内部缓存，但模块级 `re.compile` 更彻底地避免重复编译开销）；

2. **点积遍历较短的向量**：`cosine_similarity` 中点积循环改为始终遍历键数较少的 Counter，减少循环体执行次数；

3. **删除不可达冗余分支**：原代码中 `if mag1 == 0 or mag2 == 0: return 0.0` 在数学上不可达（Counter 非空时模长必 > 0），删除后简化了控制流；

4. **（实验性）n-gram 生成改用 zip 切片**：尝试用 `zip(*(text[i:] for i in range(n)))` 替代逐字符切片，实测可额外提速约 5.7%，但代码可读性下降明显。考虑到评分规则中代码可读性占 10 分，且原代码性能已在毫秒级、远低于 5 秒限制，**最终保留了更易读的原始写法**，将 zip 优化作为实验记录在此。

### 4.3 改进效果

在同一台机器、同一语料上，对核心函数 `compute_similarity` 用 `timeit` 各跑 30 次取平均：



| 版本                          | 平均耗时    | 输出答案 |
| --------------------------- | ------- | ---- |

## 六、计算模块部分异常处理说明

程序共设计 4 类异常 / 错误处理，设计目标与对应场景如下：



| 异常 / 错误             | 设计目标                               | 对应场景                   |
| ------------------- | ---------------------------------- | ---------------------- |
| 命令行参数个数错误           | 明确告知正确用法，返回退出码 1                   | 用户漏传或多余传参              |
| `FileNotFoundError` | 定位到具体缺失的输入文件，友好提示而非堆栈崩溃            | 原文 / 抄袭版文件路径不存在        |
| `PermissionError`   | 识别答案文件无写入权限的情况，给出针对性提示             | 答案文件为只读或所在目录无写权限       |
| `OSError`（输出阶段）     | 捕获其他文件读写错误（如输出路径目录不存在）             | 答案文件所在目录不存在            |
| 文件编码异常（非法 UTF-8 字节） | `errors="ignore"` 忽略坏字节，保证正常读到可读部分 | 文件混入二进制乱码、非 UTF-8 编码片段 |

> 注：
>
> `main()`
>
>  采用
>
> **分两阶段异常处理**
>
> ：第一阶段（计算相似度）只捕获输入文件的 
>
> `FileNotFoundError`
>
> ；第二阶段（写入答案）捕获 
>
> `PermissionError`
>
>  和 
>
> `OSError`
>
> 。这样输入文件缺失和输出文件失败不会互相干扰，错误提示更精确。
